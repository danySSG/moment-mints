# core — общее ядро концептов A и B (TxLINE → матч-события)

Написано 2026-07-05 (AWAKE 64) офлайн по докам, БЕЗ вызовов API (auth = действие
наружу → оператор, день-1). Node ≥18, ноль зависимостей.

## Что здесь
- `sse.mjs` — SSE-ридер (стандартный text/event-stream фрейминг).
- `statkeys.mjs` — декодер statKey (`period*1000 + baseKey`) и фаз. **✅ таблица
  BASE_KEYS 1..8 и все 19 фаз подтверждены докой 2026-07-05** — допущений в ядре
  больше нет.
- `normalize.mjs` — адаптер сырого payload'а (все догадки о форме полей собраны тут;
  при первом живом сообщении правится только этот файл).
- `events.mjs` — детектор: голы/карточки/фазы как дифф статов. Краевые случаи закрыты:
  stale seq, разрыв стрима (0→2 = два GOAL), VAR-откат (GOAL_REVOKED), подключение
  в середине матча (базлайн не эмитится), частичные апдейты (мерж).
- `replay.mjs` — CLI: NDJSON-реплей (тест без живого матча) или `--live <url>`
  (нужны env TXLINE_JWT / TXLINE_API_TOKEN после активации токена).

## Проверка

```
node --test test/test.mjs        # 10/10 зелёные (2026-07-05, после сверки с OpenAPI)
node replay.mjs test/demo-match.ndjson
```

## День-1 (оператор), что осталось до живых данных
1. Активация токена по ранбуку (../wc2026-hackathon.md): кошелёк devnet → guest JWT →
   on-chain subscribe → activate.
2. Слить вчерашний матч через `/api/scores/snapshot|updates` в NDJSON → `replay.mjs` —
   если поля не совпали, правится `normalize.mjs`; если раскладка ключей иная —
   `BASE_KEYS` в `statkeys.mjs`.
3. Дальше по концепту: A — минт-пайплайн ест события GOAL/…; B — тот же каркас поверх
   `/api/odds/stream` (детектор дельт другой, SSE/auth те же).
